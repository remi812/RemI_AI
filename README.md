# RemI AI

RemI AI — веб-приложение для персонализированного обучения. Студент выбирает тему, проходит адаптивную диагностику, получает карту навыков и рекомендации, затем может повторно проверить знания и посмотреть историю.

В релизе от 25 ноября 2026 года доступны 19 подробных тем по высшей математике, Python и теории автоматического управления, а также обзор математического моделирования. Банк включает 126 вступительных и 126 повторных заданий по 42 навыкам. Графы, вопросы и материалы для учебной группы проходят модерацию.

## Локальный запуск для разработки

Установите Python 3.10 и PostgreSQL 18. Запустите PostgreSQL и настройте доступ через `pgpass` или переменную окружения `PGPASSWORD`. В PowerShell выполните:

```powershell
git clone https://github.com/remi812/RemI_AI.git
cd RemI_AI
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt

$env:PGHOST = '127.0.0.1'
$env:PGPORT = '5432'
$env:PGUSER = 'postgres'
$env:PGDATABASE = 'remi_dev_demo'
createdb --maintenance-db=postgres $env:PGDATABASE
python -m app.pilot_admin init
python run_local.py --test
```

Откройте [локальный сайт](http://127.0.0.1:8019/). Если `createdb` отсутствует в PATH, создайте пустую базу `remi_dev_demo` через pgAdmin. Команда `init` создаёт схему, применяет миграции по 20-ю включительно и загружает учебный каталог.

Для проверки полного маршрута в своей выделенной базе с суффиксом `_demo` примените тестовые допуски. Выполните команду из корня проекта при тех же настройках PostgreSQL:

```powershell
python -c "import sys; sys.path.insert(0, 'tests'); from pilot_acceptance import synthetic_reviews; synthetic_reviews()"
```

Затем создайте профиль с вымышленной почтой, выберите тему и пройдите диагностику. Для семантического подбора установите зависимости из `requirements-model.txt`, выполните `python database/download_pilot_model.py` и `python -m app.pilot_admin index`, затем перезапустите приложение. Базовый запуск использует подбор по связям навыков.

### Модерация

На обычной установке начальные и повторные вопросы, а также разделы имеют статус pending. Для назначения роли зарегистрируйте профиль преподавателя, узнайте его student_id в таблице remi_project.students и выполните `python -m app.pilot_admin moderator --student-id N`. После входа в маршрут преподавателю доступен кабинет. Он видит версию, ключ, варианты, критерий и фазу вопроса либо курс, раздел, ссылку, описание и проверенные условия доступа. Решение с комментарием попадает в журнал. При допуске материал индексируется. Если модель установлена позже, выполните `python -m app.pilot_admin index` и перезапустите сервер.

### Диагностика и материалы

Параметры пилота REMI_VOTES=2, REMI_DEPTH=3 и REMI_LIMIT=20 задают число согласованных ответов, глубину и лимит показов. После ошибки сервер предпочитает более простое уточнение, после правильного ответа — применение навыка. При двух ошибках проверяются предпосылки. Смешанная пара требует дополнительного задания. Если свидетельств мало, результат остаётся неопределённым. Короткий ответ сравнивается с явно заданным словарём. Уже выданный вопрос исключается для этого профиля, включая незавершённую проверку. При повторном входе можно продолжить текущую сессию.

После диагностики на карте сразу видны следующий навык, его связь с целью, рекомендуемый раздел курса и причина выбора. Если осталось несколько навыков, порядок можно раскрыть в «Дальнейших шагах». Предпосылки идут перед зависящими от них шагами, общий навык встречается один раз. После повторной проверки карта показывает предыдущий и текущий результат и пересчитывает оставшиеся шаги по данным профиля.

Для каждого узла отбираются допущенные русскоязычные разделы с открытым чтением и проверенной связью с навыком. Текст раздела кодируется по названию и описанию, запрос — по цели и навыку. Косинусное сходство используется для сортировки. При пустой выборке сайт сообщает об отсутствии материала. Условия записи, оплаты или таймкоды по странице курса не додумываются.

### Проверка на вымышленных данных

Создайте отдельную пустую базу с именем, оканчивающимся на _demo, задайте PGDATABASE и выполните init. Следующий сценарий имитирует решения модератора исключительно для такого стенда. Он создаёт новые вымышленные профили при каждом запуске. Требуются зависимости из requirements-dev.txt и requirements-model.txt и скачанная модель.

```powershell
$env:PYTHONPATH = (Get-Location).Path
$env:PYTHONUTF8 = '1'
python tests/pilot_acceptance.py control derivatives programming functions algebra limits rates integrals differential-equations programming-types programming-variables programming-conditions programming-functions programming-lists control-signals control-system control-transfer control-blocks control-transients
python tests/pilot_content_review.py
python tests/retrieval_eval.py
python tests/pilot_review_acceptance.py
$env:REMI_PILOT_DB_TEST = '1'
$env:REMI_RUN_DB_TESTS = '1'
python -m unittest discover -s tests
```

Для проверки интерфейса запустите сервер на порту 8019, затем `node tests/pilot-browser.cjs` с доступным модулем playwright. REMI_CHROME задаёт путь к Chrome, REMI_HTTP_PORT — порт сайта. Браузерный сценарий на ширине 390 px начинает с двух разных профилей ТАУ, проходит производные и циклы, затем открывает все остальные подробные темы из каталога и проверяет обзор моделирования. Проверяются также ошибка загрузки материала, повтор запроса и пустая подборка. Для демонстрации с видимым окном укажите в REMI_SHOW_PROFILE новый отдельный каталог временного профиля Chrome.

Для дополнительной браузерной проверки резервного режима во втором терминале выберите ту же тестовую БД, задайте REMI_MODEL_DIR с путём к отсутствующей папке и запустите `python run_local.py --test --port 8021`. В терминале браузерного теста задайте REMI_FALLBACK_PORT=8021. Приёмочный тест pilot_review_acceptance.py также проверяет порядок двух разделов по независимому расчёту косинуса, решения и записи модератора, отказ в доступе к чужой сессии. Все его изменения в БД откатываются.

На 26 разделах и 27 размеченных запросах MiniLM дала подходящий первый результат в 21 случае (MRR 0,832), TF-IDF — в 15 (MRR 0,648). Этот тест сравнивает весь каталог без фильтра навыка. В интерфейсе сначала действуют фильтры навыка, допуска, языка и доступа. Учебный эффект у студентов предстоит измерить.

## Режимы запуска

Обычный запуск: задайте PGDATABASE и параметры PGHOST, PGPORT, PGUSER нужного экземпляра PostgreSQL и выполните `python run_local.py`. Для пароля используйте pgpass либо `python run_local.py --ask-password`. При занятом порте процесс завершится с сообщением. Другой порт задаётся через --port.

Для учебной приёмки на пустой базе задайте эти же переменные, укажите отдельное имя с суффиксом _demo, создайте базу, выполните init и проверки в разделе выше. До имитации допусков выполните `python tests/pilot_empty.py`. Затем запустите `python run_local.py --test`. Оба режима используют http://127.0.0.1:8019/ по умолчанию. Для браузерных тестов нестандартного порта укажите также REMI_HTTP_PORT. Инструкции по подготовке рабочей базы даны в database/README.md.
