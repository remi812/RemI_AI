# Домашнее задание 7
## Сбор требований к моделям машинного обучения

Учебный пример: RemI AI — платформа персонализированного обучения. Ответ подготовлен по последовательности из лекции 7 и черновику ТЗ RemI AI 0.1. Предлагаемые решения ниже являются учебными предложениями, а не утверждёнными изменениями ТЗ. Применён простой учебный формат: конкретный стандарт оформления в задании не указан.

### 1. Проблема в профессиональной области

В области образовательных технологий учащемуся бывает трудно определить, какие базовые знания мешают освоить выбранную тему. Например, ошибки при решении дифференциальных уравнений могут быть связаны с недостаточным пониманием производной. Самостоятельный выбор материалов не всегда устраняет первопричину затруднения.

В RemI AI предлагается оценивать освоение отдельных компетенций по истории ответов и использовать эту оценку при выборе следующих диагностических заданий. На основе подтверждённых пробелов система строит объяснимый учебный маршрут с учётом связей между компетенциями. По ТЗ одна ошибка не должна автоматически означать пробел.

### 2. Показатель эффективности решения

Предлагаемый основной показатель — доля учащихся, которые успешно проходят независимую повторную проверку целевой компетенции после обучения по маршруту. Для проверки пользы решения её следует сравнить с результатом обычного маршрута при сопоставимых начальных знаниях и условиях обучения.

Для самой модели дополнительно можно измерять долю правильно определённых состояний освоения по сравнению с независимой экспертной оценкой. Отдельно важно учитывать ошибки двух видов: пропущенные пробелы и ошибочно объявленные пробелы. Одной общей точности недостаточно, если большинство примеров относится к одному состоянию.

Численные целевые значения пока не задаются: в ТЗ они не утверждены, а исходных результатов пилота ещё нет.

### 3. Как проблема решается сейчас

Типичный способ — обычные тесты, самостоятельный разбор ошибок и консультация преподавателя. Преподаватель сопоставляет ответы с темами и советует, что повторить. Это описание обычного учебного процесса, а не утверждение о проведённом исследовании пользователей RemI AI. Реальный исходный процесс и его показатели предстоит выяснить на интервью.

### 4. Можно ли обойтись правилами «если/то»

Да, для первой версии можно использовать правила: проверять ответы по ключам, собирать несколько подтверждений затруднения и переходить к заданиям по предварительным компетенциям. Учебный маршрут по графу зависимостей тоже можно строить правилами.

Поэтому необходимость обучения собственной ML-модели пока не доказана. ML имеет смысл сравнить с таким базовым решением, когда появится достаточно качественных данных. Потенциальная польза — учитывать сочетания результатов нескольких заданий и различия в сложности вопросов. Например, одинаковое число ошибок на простых и сложных заданиях может означать разный уровень освоения. Улучшение нужно подтвердить экспериментом; сложность задачи сама по себе не доказывает необходимость ML.

### 5. Имеющиеся и желательные данные

Сейчас в проектной папке доступны концепция и черновик ТЗ. Наличие готовой обучающей выборки ответов учащихся не подтверждено. Материалы курса в папках проекта являются учебными источниками, но сами по себе не являются размеченным датасетом для диагностики.

Для разработки понадобятся:

- проверенный перечень компетенций и связей между ними;
- проверенные задания с указанием компетенции, критериев ответа и сложности;
- история диагностик: обезличенный идентификатор учащегося, задания, ответы, результаты проверки и порядок предъявления;
- независимые оценки освоения компетенций, полученные по отдельным проверочным заданиям и экспертной рубрике;
- для оценки пользы маршрутов — сведения о пройденных материалах и результатах повторных проверок.

Данные должны охватывать разные уровни подготовки. Нужный объём следует определить по пилоту, а не назначать произвольное число записей. Для оценки качества данные разных учащихся нужно разделять между обучением и проверкой, чтобы модель не проверялась на уже знакомых ей людях.

### 6. Формулировка задачи в терминах ML

Предлагается задача классификации с учителем: по диагностической истории учащегося оценить, освоена ли конкретная компетенция. Модель может выдавать вероятность освоения. При недостаточных или противоречивых данных система должна запрашивать дополнительные свидетельства и показывать неопределённость.

Статусы карты «не оценено» и «требует уточнения» описывают достаточность данных; их не обязательно превращать в классы обучаемой модели. Построение маршрута по зависимостям компетенций остаётся отдельной логикой системы.

### 7. Целевая переменная и разметка

Предлагаемый target: 1 — компетенция освоена по независимой проверке; 0 — освоение не подтверждено по согласованной рубрике. Это учебный вариант постановки; критерии и пороги ещё необходимо согласовать с предметным экспертом.

Преподаватель оценивает несколько проверенных заданий, относящихся к конкретной компетенции, по заранее заданным критериям. Спорные случаи требуют дополнительной проверки и до уточнения не получают окончательную метку. Отрицательная метка не должна назначаться по одной случайной ошибке.

Для модели используются только ответы, доступные до независимой проверки. Ответы на задания, которыми сформирована итоговая метка, нельзя одновременно подавать модели как исходные признаки: это даст завышенную оценку качества.

### 8. Возможные этические и юридические риски

История ответов и профиль могут содержать персональные данные. Возможны раскрытие результатов обучения, использование данных без понятного пользователю основания и передача лишних сведений внешнему поставщику модели. Состав данных, доступ, сроки хранения, удаление и условия передачи необходимо определить до эксплуатации. При работе с несовершеннолетними потребуется отдельно уточнить применимые требования.

Ошибочная оценка способна навязать учащемуся лишнее повторение или пропустить важный пробел. Поэтому оценку следует объяснять, показывать неопределённость и давать возможность повторной проверки. По ТЗ система не предназначена для официальной аттестации.

Модель может работать хуже для пользователей с другой языковой подготовкой или особыми образовательными потребностями, если такие примеры плохо представлены в данных. Это нужно учитывать при сборе данных и оценке качества. Личные характеристики, не необходимые для диагностики знаний, не следует добавлять без обоснования.

Для учебных материалов и заданий необходимо учитывать права авторов и условия использования. Генерируемые задания должны проходить проверку до предъявления учащемуся, как предусмотрено ТЗ.

Перечисленные пункты — анализ возможных рисков, а не заключение о юридическом соответствии продукта.

### Связь с проектом

Работа уточняет возможную ML-постановку диагностики RemI AI, требования к данным и разметке. Практический следующий шаг — согласовать компетенции и критерии освоения, затем собрать пилотные данные и сравнить простые правила с ML. Обучение собственной модели до этого не является обязательным условием MVP.
