# Учебная база RemI AI для MVP

SQL-файл `01_создание_и_данные.sql` создаёт отдельную схему `remi_project` внутри выбранной базы PostgreSQL и заполняет её небольшим набором вымышленных данных. `03_расширение_MVP.sql` расширяет эту базу: добавляет историю оценок знаний и уверенности, версии заданий, журнал модерации, маршруты и их материалы. Никакие реальные пароли не добавляются.

## Запуск в pgAdmin

1. Откройте сервер PostgreSQL и выберите базу проекта `RemI_AI`.
2. На пустой базе для первоначального создания выполните целиком `01_создание_и_данные.sql`, а затем `03_расширение_MVP.sql`. На текущем компьютере оба файла уже применены в `RemI_AI`: повторно их запускать не нужно.
3. Обновите дерево объектов: таблицы находятся в Schemas → remi_project → Tables.
4. Откройте `02_примеры_запросов.sql` или `04_запросы_MVP.sql` в Query Tool и выполняйте запросы по одному.

Дополнительное учебное наполнение высшей математики находится в `05_высшая_математика.sql`; на текущем компьютере этот файл уже применён. Для новой базы его запускают после файлов 01 и 03.

Русскоязычные курсы добавлены файлом `06_русскоязычные_курсы.sql`, который выполняется после файла 05. На текущем компьютере он уже применён.

Файл `07_курс_МГУ_недоступен.sql` помечает курс МГУ как недоступный для записи и отклонённый для рекомендаций. На текущем компьютере он уже применён; статус необходимо пересматривать, если запись откроется вновь.

Файл `08_основы_программирования.sql` добавляет учебные компетенции и вопросы по Python, а также русскоязычные курсы. На текущем компьютере он уже применён; при создании новой базы выполнять после 01 и 03. Курсы и вопросы ожидают проверки, зачисление на курсы лично не проверялось.

Файл `09_теория_автоматического_управления.sql` добавляет компетенции, вопросы и материалы по ТАУ. На текущем компьютере он уже применён; при создании новой базы выполнять после 01 и 03. Содержание ожидает экспертизы. Возможность записи на курс по основам ТАУ на Stepik не подтверждена; курс моделирования требует SimInTech.

Файл `10_учебные_сценарии.sql` добавляет двух вымышленных студентов и два маршрута с ответами, составленные вручную. На текущем компьютере он уже применён; при создании новой базы выполнять после файлов 01, 03, 05, 06 и 09. Сценарии не являются настоящей диагностикой, а привязанные материалы ожидают проверки. Запросы для сравнения находятся в `11_сравнение_сценариев.sql`.

Файл `12_синтетические_студенты.sql` добавляет набор `demo-150-v1`: 150 вымышленных студентов, их сессии, синтетические ответы и шаблонные маршруты. Он уже применён; на новой базе выполняется после файлов 01, 03, 05, 08 и 09. Для выборок используйте `13_запросы_по_синтетическим_студентам.sql`. Таблица `synthetic_students` и отметки `synthetic-demo-150-v1` позволяют исключать эти данные из аналитики реальных пользователей. Это учебная имитация: сайт и диагностический алгоритм не создавали эти записи, а вопросы ещё не прошли модерацию.

Файл `14_студенты_аттестация.sql` добавляет ещё 150 вымышленных студентов в набор `demo-150-v2` с сессиями, ответами и маршрутами. На текущем компьютере он уже применён; для новой базы необходимы файлы 01, 03, 05, 08 и 09. Данные остаются синтетическими и не являются результатом реальной диагностики. Примеры запросов для промежуточной аттестации находятся в `15_запросы_для_аттестации.sql`.

Данные OULAD изучены отдельно в `../research/oulad/`. В базе `RemI_AI` создана отдельная схема `oulad_research` с метаданными и сводными показателями, без строк отдельных студентов. Запросы к ней находятся в `../research/oulad/oulad_queries.sql`; исходные данные не смешаны с пользователями RemI AI.

Файлы создания и расширения выполняются каждый в своей транзакции и предназначены для однократного запуска. Первый не перезаписывает существующую схему; повторное применение расширения также завершится ошибкой. Перед изменением существующей базы делайте резервную копию.

Данные, ответы, пример оценки, маршрут и связи являются учебными примерами, а не результатом реальной диагностики или проверенной преподавателем моделью предметной области. Вопросы имеют статус `pending` и требуют проверки перед использованием в настоящей диагностике. Первые демонстрационные материалы не имеют ссылок. По математике добавлены ссылки на англоязычные и русскоязычные материалы; предметная модерация и проверка текущих условий доступа ещё не проведены. Новые связи предпосылок проверяются на циклы.

База хранит данные для MVP, но не реализует само приложение: вход и безопасное хеширование паролей, автоматическую диагностику, проверку ИИ-заданий, создание новых версий вопросов и маршрутов, проверку ссылок и разграничение прав ещё нужно разработать. Приложение должно обеспечивать согласованность версии вопроса с модерацией, показывать только проверенные задания и ресурсы, связывать оценку только с ответами соответствующего студента и компетенции и не назначать маршруту чужую оценку. Эти правила пока не полностью обеспечиваются ограничениями базы.
