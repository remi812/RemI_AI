# Домашнее задание 14 — OLAP, звезда и снежинка

Предметная область — персонализированное обучение RemI AI. Цель учебной аналитической модели: считать количество ответов и средний результат по датам, учащимся, заданиям и компетенциям. Пример вопроса: как меняется средняя оценка ответов по дисциплинам за месяц? Это проектирование хранения истории диагностики; полноценный кабинет групповой аналитики преподавателя не добавляется к MVP.

Использован простой учебный формат: конкретный стандарт оформления условием не задан. SQL приведён в файле «Домашнее задание 14.sql». Модели являются альтернативами и расположены в независимых схемах.

## Зерно факта и меры

Одна строка fact_answer — один отправленный ответ одного учащегося на одно задание в конкретную дату. source_answer_id — уникальный идентификатор события из источника, предотвращающий повторную загрузку одного ответа. answer_key — технический ключ аналитического хранилища.

Мера answer_count всегда равна 1. Её сумма даёт число отправленных ответов. normalized_score — оценка ответа в диапазоне от 0 до 1; NULL означает, что ответ пока не оценён. AVG пропускает такие значения, поэтому рядом со средним следует показывать COUNT(normalized_score) и общее число ответов. Средние групп нельзя усреднять без учёта их размеров: для общего среднего нужны сумма оценок и число оценённых ответов.

Нормированная оценка — учебное предложение, а не утверждённая рубрика ТЗ. Перевод в диапазон 0–1 нужно согласовать с экспертом; одинаковый диапазон сам по себе не делает задания разной сложности сопоставимыми. Оценка отдельного ответа не является подтверждённым статусом освоения компетенции: по ТЗ для этого нужны дополнительные свидетельства.

## Схема звезды — hw14_star

Центр — fact_answer. Четыре непосредственно связанных измерения:

| Таблица | Содержание |
|---|---|
| dim_date | Дата, день, месяц, квартал, год |
| dim_student | Технический ключ и псевдонимизированный идентификатор учащегося |
| dim_question | Идентификатор и версия задания, текст, код и название типа |
| dim_competency | Идентификатор и название компетенции, идентификатор и название дисциплины |

Измерения не ссылаются друг на друга. Тип задания хранится непосредственно в измерении задания; дисциплина — в измерении компетенции. Это денормализация: название дисциплины может повторяться для нескольких компетенций. Зато для анализа не требуется дополнительное соединение со справочником дисциплин.

## Схема снежинки — hw14_snow

Таблица fact_answer также имеет четыре непосредственные связи с dim_date, dim_student, dim_question и dim_competency. Две ветви продолжаются на дополнительный уровень:

- fact_answer → dim_question → dim_question_type;
- fact_answer → dim_competency → dim_discipline.

Таким образом, получены одна таблица фактов, четыре основных измерения и два дополнительных измерения нижнего уровня. Типы задания и дисциплины хранятся в справочниках, что уменьшает повторение их названий. Для получения названия дисциплины или типа потребуется ещё один JOIN.

## Ключи и типы данных

Измерения и факт имеют PRIMARY KEY. Четыре внешних ключа факта ссылаются на четыре основных измерения. В снежинке добавлены два внешних ключа к нижнему уровню. source_* связывают аналитические сущности с источником; это логические идентификаторы, а не внешние ключи на учебные альтернативы домашки 13.

Идентификаторы источника представлены TEXT как учебный выбор, поскольку окончательная операционная схема не утверждена. В dim_date дата уникальна, date_key — целочисленный ключ, например 20261030. Согласованность дня, месяца, квартала, года и ключа с calendar_date должен обеспечить процесс загрузки. CHECK задаёт лишь простые допустимые диапазоны.

В dim_student не копируются имя, адрес почты и пароль. Токен должен быть стабильным и формироваться источником; он не гарантирует полной анонимности, а доступ к сопоставлению с пользователем требует отдельного решения.

## Границы учебной модели

Для упражнения одному ответу назначается одна основная компетенция, а компетенции — одна основная дисциплина. Такой выбор не утверждает, что в реальном проекте исключены междисциплинарные связи. При нескольких компетенциях у задания потребуется согласовать правила распределения факта, чтобы не удвоить число ответов. Соответствие задания основной компетенции и выбор даты проверяет загрузка: независимые внешние ключи не обеспечивают такую предметную согласованность.

Версия задания включена в уникальный ключ (source_question_id, version_number), чтобы при изменении текста можно было сохранять отдельную строку и привязывать факты к нужной версии. Обновление названий компетенций и дисциплин в этой упрощённой модели предполагается по SCD Type 1, без истории названий. Если важны прошлые названия и связи, потребуется проектирование SCD Type 2. Повторная проверка уже отправленного ответа обновляет его оценку; история пересмотра оценок здесь не моделируется.

Загрузка данных, правила оценивания и пользовательские отчёты не реализуются в рамках этого задания: по условию требуется CREATE TABLE. Для небольшой предметной витрины RemI AI в первую очередь можно рассмотреть звезду из-за простоты запросов, а решение о внедрении принимать после согласования аналитических сценариев.
